# Agent guide

## Map
- Work inside this repository; do not inspect parent directories.
- `rust/` contains the implemented library and CLI (Rust 2024). Run Cargo there;
  there is no root Cargo workspace.
- `rust/src/`: `public_key_bytes.rs` owns the 32-byte type; `encode.rs`/`decode.rs`
  implement codecs; `public_key_encoding.rs` and `public_key_format*.rs` define
  encodings/aliases; `main.rs` owns CLI behavior. Interop impls are included from
  `public_key_bytes/`.
- Dart, JS/TS, Python, and Ruby packages are scaffolds. Ruby has a separate Cargo
  workspace; its `edky_rs` dependency uses crates.io, not local `rust/`.
- Use Bun for `js/`, uv/Python 3.14+ for `python/`, Dart 3.11+ for `dart/`, and
  Bundler/Ruby 4.0+ for `ruby/`. Package versions currently differ.

## Implementation rules
- Preserve `#![no_std]`; use `core`, gate allocation on `alloc`, and gate `std`
  usage explicitly. Keep dependencies minimal and integrations optional.
- Defaults enable `std` and all encodings, not all interops. The CLI requires
  `cli`. `iroh` enables the format alias; `iroh1` enables the crate integration.
- Codec changes must keep Cargo features, enum variants/`VARIANTS`, the format
  registry, encode/decode arms, error conversions, and sample vectors consistent.
- `PublicKeyBytes` holds raw bytes, not a cryptographically validated point.
  Display/FromStr and Serde use hex. Parsing must reject wrong decoded lengths;
  never silently pad/truncate or introduce input-dependent panics.
- Preserve canonical prefixes and aliases in `public_key_formats.rs` and
  `data/samples.csv`. Add focused regression tests for changed behavior, including
  malformed input and relevant feature combinations.
- Document every new/changed public symbol with rustdoc. Put detailed contracts,
  feature requirements, errors, and examples on the relevant modules/types.
  README additions require exceptional justification; length is not value.

## Checks
For Rust changes, run from `rust/`:
```sh
cargo fmt -- --check
cargo test --locked --features cli
cargo clippy --locked --all-targets --features cli
rake check
```
`rake check` needs Ruby 3.4+ and the `csv` gem; it checks every sample-format pair.
`rust/tests/decode.rs` covers malformed inputs and decoded lengths; `rake check`
additionally exercises CLI conversions across every format pair.

For feature/dependency changes, also check `--no-default-features`,
`--no-default-features --features alloc`, each affected feature in isolation, and
`--all-features` with `cargo check --locked`. Known baseline failures: bare
no-default (allocating FromStr derive), base32z-only (error impl cfg), and
clientele without std. Report existing failures separately from regressions.

For JS changes: `bun run build` and `bunx tsc --noEmit` in `js/`.
Other language test suites are unfinished; do not mistake empty suites for coverage.

## Generated files
- Samples: edit `data/samples.csv`; run `rake` in `data/` to regenerate JSON/PSV/YAML.
- READMEs: edit `.config/readmer/*.liquid` or its language subdirectory, then run
  `make -B README.md` in the affected package/root (requires `readmer`).
  For CLI help snippets, build with `cli`, then run from the root:
  `PATH="$PWD/rust/target/debug:$PATH" rake -B codegen` (force refresh of existing files).
- Releases: edit `dist-workspace.toml`; regenerate `.github/workflows/release.yml`
  with the configured cargo-dist version. `ruby/.gemspec.yaml` is generated by its Makefile.
- Regenerate only affected outputs; preserve unrelated changes and lockfile versions.
